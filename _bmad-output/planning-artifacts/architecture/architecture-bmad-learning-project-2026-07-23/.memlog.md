Password change (FR35) invalidates both via the existing SessionVersion bump.
- (decision by user) refresh token is non-rotating — reuses the SessionVersion JWT mechanism already built, no new server-side token table/reuse-detection. Explicit trade-off accepted: a stolen refresh cookie stays valid up to 15 days or until next password change, in exchange for no added rotation/reuse-detection complexity
