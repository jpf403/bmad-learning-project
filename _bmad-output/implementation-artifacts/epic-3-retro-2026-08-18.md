## What Went Well

- **Per Jack: the most fluid epic of the project.** Stories took less effort than in Epic 1 or Epic 2, and code reuse was frequent and visible.
- **Story 3.1's repository-first foundation paid off completely.** Every operation Epic 3 needed (`Search`, `AdminUpdate`, `AdminCreateBarber`, `AdminSoftDeleteAccount`, the appointment cascade) was built and fully tested once in 3.1. Stories 3.2 through 3.5 added **zero** Service or Repository changes — each was pure Controller + DTO + frontend work on an already-proven foundation.
- **Frontend patterns compounded the same way.** Attribute-based `[Authorize(Roles = "Admin")]` gating (established 3.2), the `AccountApi.js` fetch/envelope shape, and the `AdminPanel.jsx` page structure were all set once and extended, not reinvented, through 3.5 — directly enabling 3.4 and 3.5's zero-review-finding runs.
- **`AccountService` took on its first Service-to-Service dependency** (`IBookingService`, for the demote/delete appointment cascade) — a deliberate, well-reasoned architectural call rather than a layering violation, documented inline in Story 3.1's Dev Notes.
- **`BarberSeedService` cleanly retired.** Per Epic 2's retro action item, the dev-only seeding scaffolding was deleted the moment Story 3.4 shipped a real barber-creation path — no lingering scaffolding left behind.
- **The one real blocker (the Select-in-Dialog focus recursion bug) was solved with root-cause rigor, not a quick patch.** Confirmed by isolated repro, then verified against `@radix-ui/react-select@2.3.4`'s own source (its `FocusScope` is unconditionally `trapped: context.open`, no opt-out when nested in an open `Dialog`). The resulting hand-rolled-overlay workaround was documented and explicitly flagged for Stories 3.4/3.5 to check — both confirmed "not applicable" and moved on without re-deriving the investigation.
- **Deferred-work discipline held strong from Epic 2.** Every story re-read `deferred-work.md` at kickoff and resolved items exactly when the right story arrived (null-guarding closed by 3.3/3.4's DTO validation; the customer soft-delete cascade gap closed by 3.5).

## Challenges

- **The Select-in-Dialog bug was the epic's one significant time sink.** Per Jack: it took real effort to run down, but the outcome (root-caused, documented, and non-recurring for the rest of the epic) was worth the cost.
- **Story 3.3 needed a UI rework after review** — the original two-sections-at-once popup layout (identity fields + password fields both visible) was too tall; reworked so the password section replaces the identity section instead of stacking below it.
- **Minor, accepted gaps remain open** (see Readiness Assessment) — none blocking, all reviewed and consciously left as-is.
